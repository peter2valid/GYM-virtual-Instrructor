# Exercise Import Plan

## Two Content Sources

### Source 1: `free-exercise-db`
- 873 exercises as individual JSON files + combined `dist/exercises.json`
- Schema: `{ id, name, category, level, force, mechanic, equipment, primaryMuscles[], secondaryMuscles[], instructions[], images[] }`
- Images: `ExerciseName/0.jpg` and `ExerciseName/1.jpg` (static start/end poses)
- License: Unlicense (public domain)
- Categories: strength, cardio, stretching, powerlifting, plyometrics, olympic weightlifting, strongman

### Source 2: `gif and images`
- ~180 exercise GIFs (animated movement demos)
- ~60 anatomy PNGs (muscle diagrams per exercise)
- 146 icon PNGs (muscle groups, equipment, activity types)
- Organized by body region: Shoulders, Arms, Chest, Legs, Back, Abs_Core

## Mapping to Database Tables

### Source 1 → `exercises` table

| JSON field | DB column |
|-----------|-----------|
| `id` | `source_id` |
| `"free-exercise-db"` (literal) | `source_name` |
| `name` (slugified) | `slug` |
| `name` | `name` |
| `category` | `category` |
| `level` | `level` |
| `force` | `force` |
| `mechanic` | `mechanic` |
| `equipment` | `equipment` |
| `primaryMuscles` | `primary_muscles` (jsonb) |
| `secondaryMuscles` | `secondary_muscles` (jsonb) |
| `instructions` | `instructions` (jsonb) |
| `images[0]` → hosted URL | `image_1_url` |
| `images[1]` → hosted URL | `image_2_url` |

The `slug` is generated by slugifying the exercise `name`:
```
"3/4 Sit-Up" → "3-4-sit-up"
"Barbell Back Squat" → "barbell-back-squat"
```

### Source 2 → `exercise_media_map` table

GIF files map to exercises via name matching:

| GIF filename | Exercise slug match strategy |
|-------------|------------------------------|
| `barbell_bench_press.gif` | `barbell-bench-press` |
| `incline-cable-fly.gif` | `incline-cable-fly` |

The import script uses fuzzy slug matching:
1. Normalize GIF filename (strip extension, replace `_` and `-` with spaces, lowercase)
2. Compare against exercise slugs
3. If confident match (normalized equality), insert into `exercise_media_map` with `is_preferred = true`
4. If ambiguous, log to review file — do not insert

Anatomy PNGs follow the same matching but go into `anatomy_image_url`:
- `incline-cable-fly-muscles.png` → linked to same exercise row, `anatomy_image_url` column

---

## Handling Mismatches

Not every exercise in the DB has a GIF. Not every GIF has a DB entry.

### Exercise without GIF
- Fallback chain in `resolveExerciseMedia()` handles this
- If no `exercise_media_map` row: falls back to `exercises.image_1_url`
- If no image either: SessionScreen renders category icon placeholder

### GIF without DB exercise
- Logged during import to `scripts/unmatched-media.log`
- Can be inserted into `exercises` manually or via a future manual-entry tool
- Do not block the rest of the import

### Resolution
The architecture intentionally supports this mismatch. The `exercise_media_map` table is additive — it enriches the `exercises` table but is not required for the app to function.

## Import Scripts (stubs ready for implementation)

### `scripts/import-exercises.ts`

```typescript
// Reads: free-exercise-db/dist/exercises.json
// Writes: exercises table rows (batch upsert by source_id + source_name)
// Usage: npx tsx scripts/import-exercises.ts
```

Key steps:
1. Read `dist/exercises.json`
2. For each exercise, generate `slug` (slugify name, ensure uniqueness)
3. Upsert into `exercises` using `(source_id, source_name)` as conflict key
4. Log result summary

### `scripts/import-exercise-media.ts`

```typescript
// Reads: gif and images/ directory tree
// Writes: exercise_media_map rows
// Usage: npx tsx scripts/import-exercise-media.ts
// Requires: exercises table already populated
```

Key steps:
1. Walk `gif and images/` directory
2. For each GIF: normalize filename → match against `exercises.slug`
3. For confident matches: upsert into `exercise_media_map` with `media_type='gif'`, `is_preferred=true`
4. For each anatomy PNG: link to same exercise, set `anatomy_image_url`
5. Output `scripts/unmatched-media.log` for manual review

## Future: Cloudflare R2 Migration

When GIFs are converted to MP4/WebM and uploaded to R2:

1. Upload converted file to R2 bucket
2. Get public R2 URL
3. Update `exercise_media_map` row:
   - `media_url` → R2 URL
   - `media_type` → 'mp4' or 'webm'
4. Optionally keep the GIF row with `is_preferred = false` for fallback

No schema migration needed. No UI changes needed. The media resolution chain handles it transparently.

## Icons

The `Icons/` folder contains 146 PNGs for muscle groups, equipment, and activities. These are not imported into the database. They are served as static assets from `public/icons/` and referenced directly in UI components where needed (e.g. `icon-chest.png` for category display, `icon-dumbbell.png` for equipment indicators).

To use them:
1. Copy relevant icons from `gif and images/Icons/` to `public/icons/`
2. Reference via `<img src="/icons/icon-chest.png" />` or Next.js `<Image>`
